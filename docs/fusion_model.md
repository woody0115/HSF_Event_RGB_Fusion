# 依可靠度加權的 Event + RGB 融合：從資料推導的數學模型

2026-11-14。訊號統計用 `tools/fusion_signal_stats.py`：

- **設計依據是驗證集**（整趟行車的 zurich_city_05 + 10，`--split val --stride 3`，2,209 張影像、10,388 個框）。
- test（`--split test --stride 5`，2,784 張、18,742 個框）只用來確認方向相同。

結果在 `runs/diag/fusion_signal_stats_{val,test}.json`。模型表現的數字（F1、F2）來自 `runs/eval_conditions.json`（test）。

**推論**：

- 可靠度不是由「整張圖的亮度」決定（F1），而是由**每個位置、每個場景的訊號品質**決定（F2、F3）。所以依光線分類切換、或每通道一個閘門的 IllumGate 都不夠。
- event 只在少數地方有用（F3）。直接相加（add）會把大部分是背景運動的 event 特徵，以和 RGB 相同的權重加進來，等於加入雜訊。

## 2. 模型：兩個帶雜訊的觀測

在第 k 個尺度、位置 x，兩條分支（各自對齊後）的特徵看成同一個潛在特徵 z 的兩個觀測：

```
f_r(x) = z(x) + ε_r(x),   ε_r ~ N(0, σ_r²(x))
f_e(x) = z(x) + ε_e(x),   ε_e ~ N(0, σ_e²(x))     ε_r、ε_e 互相獨立
```

最大概似（同時也是最小均方誤差）的融合是**精度加權**，精度 π = 1/σ²：

```
ẑ(x) = w(x)·f_r(x) + (1 − w(x))·f_e(x),   w = π_r / (π_r + π_e) = sigmoid(ℓ),   ℓ = log π_r − log π_e
Var(ẑ) = 1 / (π_r + π_e) ≤ min(σ_r², σ_e²)
```

**權重正確時，融合不會比較好的那個單一模態差。** 拿 add 比較（等於 w = 1/2，再乘以 2 倍尺度）：

```
Var_add ∝ (σ_r² + σ_e²) / 4   >   σ_r²      當 σ_e² > 3·σ_r²
```

event 比 RGB 弱很多時（32.9 對 53.9），add 就會比只用 RGB 還差，和我們觀察到的 add 52.3–53.0 低於 RGB 53.9 一致。
interlaken_00_a 則是反過來（σ_e < σ_r），add 卻沒有能力把權重移到 event，所以比兩者都差（F2）。

## 3. 由感測器物理推導 σ²（可直接從輸入算出）

### RGB

像素值 I = g·(Φ + n_shot) + n_read，其中 g 是增益，所以變異數 ≈ g·I + σ_read²，飽和像素的資訊完全遺失。
特徵的可靠度正比於局部對比雜訊比的平方：

```
π_r(x) ∝ CNR_r(x)² · (1 − s(x)),     CNR_r = σ_loc(I) / σ_noise(I),   s = 飽和像素比例
```

- σ_loc：局部（例如 7×7）灰階標準差。
- σ_noise：直接從影像估計（Laplacian 的 MAD，Immerkær 1996），不需要相機增益等資訊。

### Event

只有對數亮度的變化達到門檻 θ，像素才會產生 event：|Δ log L| ≥ θ。

```
訊號 event 數  n_s ≈ |∇log L · v|·Δt / θ          （與整體亮度縮放無關：log(γL) 的變化 = log L 的變化）
雜訊 event 數  n_n = r_n(L)·Δt                    （背景活動，暗處較多）
π_e(x) ∝ SNR_e(x)² = n_s² / (n_s + n_n)            （Poisson）
```

從 GEAR 就能估計：

- n(x)：由 num 通道反解，n = atanh(v)·255/c。
- n_n(x)：用大窗口內低百分位數的 event 量，當作背景。
- n_s = max(n − n_n, 0)。

**由資料擬合的雜訊模型（F5）**：

```
r_n(L) ∝ L^(−α)
驗證集：夜間亮度約是白天的 0.41 倍，背景 event 約是 2.24 倍  →  α = ln 2.24 / ln(1/0.41) ≈ 0.90
test：  夜間亮度約是白天的 0.30 倍，背景 event 約是 2.05 倍  →  α ≈ 0.60
```

兩者不同，所以 α 只當作 0.6–0.9 的範圍。實作時用驗證集的 0.9，或在訓練集上逐序列擬合。

### 閘門

```
ℓ_k(x) = a_k·log CNR_r(x) − b_k·log SNR_e(x) + c_k·log(1 − s(x)) + d_k + δ_k(x)
w_k(x) = sigmoid(ℓ_k(x))
```

- 物理先驗：a = b = 2、c = 1、d = 0。每個尺度只有 4 個可學參數。
- δ_k(x)：從兩模態特徵學的殘差修正，小卷積、初始為 0。
- 訊號量在對應的尺度上做平均池化（P3／P4／P5）。

**用量測值代入（中位數）**：

| 光線 | 驗證集：ℓ ／ w_r | test（確認用）：ℓ ／ w_r |
|---|---|---|
| 白天 | SNR_e ≤ 0 → w_r ≈ 1 | 2·ln(4.48 / 0.27) = 5.62 ／ 0.996 |
| 偏暗 | 2·ln(4.42 / 0.50) = 4.36 ／ 0.987 | 2·ln(3.77 / 0.46) = 4.21 ／ 0.985 |
| 夜間 | 2·ln(4.08 / 0.66) = 3.64 ／ 0.974 | 2·ln(4.37 / 2.21) = 1.36 ／ 0.80 |

中位數下，event 的權重只有百分之幾到 20%。重點不是平均權重，而是**少數 event 可靠的位置與場景**（例如夜間車燈、interlaken_00_a）可以拿到高權重；add 則對所有位置一律 50%。

這和實驗結果一致：融合只在夜間有幫助（add lr 1e-3：夜間 +3.2，白天 −1.0）。在 interlaken_00_a 這種 event 比 RGB 可靠的場景，閘門可以逐位置把權重移到 event。

## 4. 平衡兩個模態的訓練（梯度分析）

融合後的特徵是 F = w·f_r + (1 − w)·f_e，所以 event 分支的梯度是

```
∂L/∂θ_e = (1 − w)·(∂L/∂F)·(∂f_e/∂θ_e)
```

RGB 一旦能單獨把 loss 降下來，∂L/∂F 就趨近 0，event 分支就學不到東西（gradient starvation）；加上精度權重後 (1 − w) 又更小。對策：

1. **每條分支各自加輔助偵測 loss**：L = L_fuse + λ·(L_r + L_e)，λ 從 0.5 逐漸降到 0。
2. 或用學到的不確定度加權：L = Σ_m L_m / (2σ_m²) + log σ_m（Kendall et al. 2018），讓 σ_m 和第 3 節的物理估計一致。

## 5. 符合物理的低光資料增強

event 只看對數亮度的變化，所以把整體亮度縮放 γ 倍，**訊號 event 不變，只有雜訊增加**。可以從白天影像合成可信的夜間樣本：

```
RGB:    I_lin = (I/255)^2.2;   I'_lin = γ·I_lin + N(0, k·γ·I_lin + σ_read²);   再乘回增益 1/γ_ae、gamma 編碼、裁切
Event:  訊號不變；每個像素加 Poisson((γ^(−α) − 1)·n_bg,day) 個雜訊 event（α ≈ 0.9，由驗證集擬合，見第 3 節）
        → 先把 GEAR 反解回 counts，加雜訊後再編碼回去
```

γ 從 [0.15, 1] 抽樣，大約 20% 的訓練影像套用。
這是讓網路學會「RGB 變差時要依賴 event」最直接的方法，因為真實的夜間訓練資料很少（train_core 只有 zurich_city_03、09，約 6,000 張）。

## 6. TFS 與 Kalman filter 的對應

GRU 的更新閘門 z_t 相當於 Kalman gain：K_t = P_t / (P_t + R_t)，其中 R_t 是這一張的量測雜訊。
所以可以把更新閘門的偏差項設成 β·log SNR_e(x)：

- 這一張 event 可靠時，多用這一張。
- 不可靠時，多保留記憶。

## 7. GEAR 參數

- F6 顯示沒有飽和，但每個像素約 4–6 個 event 時，num 只用到約 35／255 階，解析度偏低。
- 可以考慮把 c 從 8 提高到 16。改之前，要先量 n 的 99 百分位數，確認不會開始飽和：c = 16 時，n ≥ 55 就會飽和。
- h 對沒有 event 的像素永遠不衰減（f = 1）。夜間背景雜訊約 3.2 個／張，h 會像隨機漫步一樣累積。可以加一個很小的固定衰減：f = exp(−n/τ − λ₀)。

前提：用乾淨的評估（整趟行車的驗證集、用 train_core 重訓的單流初始權重；`tools/run_paper_schedule.sh INIT=_val`）。

| 組別 | 內容 | 預期 |
|---|---|---|
| R0 | add、AF（乾淨基準） | – |
| R1 | 精度加權閘門，只用物理先驗（δ = 0，只學 a、b、c、d） | 白天 ≈ RGB，夜間 > add |
| R2 | R1 + 學習殘差 δ | interlaken_00_a 這類序列明顯提升 |

**檢查方式**：

- 逐序列算學到的 w̄_r，和量測的 CNR_r²/SNR_e² 比，算相關係數。
- 分光線、分序列報告結果，尤其是 interlaken_00_a、zurich_city_12_a。

## 9. 限制

- CNR_r 沒有考慮動態模糊；不過 F2 的 interlaken_00_a 顯示，RGB 有時會因為模糊、反光等原因失效，這部分交給學習殘差 δ 處理。
- 框內的 SNR_e 用整個框平均，物體邊緣的 event 會被稀釋。
- 高斯、彼此獨立的假設只是近似；兩模態的錯誤其實有相關（例如兩者都看不到被遮擋的物體）。
- 設計只用驗證集的數字。F1、F2 的模型表現是舊的 test 評估，只用來說明問題；新模型的超參數（a、b、c、d 的初值、α、增強比例）都不能看 test 來調整。

## 10. 實作與三輪迭代（2026-11-14，分支 `reliability-fusion`）

共同設定：乾淨初始權重（train_core 訓練的單流）、5 epoch、lr 1e-3、warmup 1、seed 0，驗證集挑權重，決定只看驗證集。
基準 `add`：驗證集 42.7，test 51.1。

### 第 1 輪：凸組合閘門（`rel_add`，`ReliabilityGate`）

第 2–3 節的閘門照字面實作：neck = w·f_r + (1 − w)·P(f_e)。驗證集 42.2（test 49.9）。event 權重平均只有 4–5%，
a、b、c、d 五個 epoch 只動了 0.02，模型退化成 RGB 單流。

**檢討**：第 2 節假設兩個模態是同一個潛在特徵的兩次觀測，但 `add` 比 RGB 單流好，表示兩者帶有互補的資訊；
凸組合給 event 多少就扣 RGB 多少，把互補的部分壓掉了。另外 n_bg 用全畫面平均，把自身運動造成的邊緣 event
也當成雜訊，SNR 被低估；純量的梯度太小，學不動。

### 第 2 輪：各自縮放（`rel2_add` ／ `relp2_add`，`ReliabilityGateV2`）

改成兩個獨立的 Wiener 增益，ρ 為一個 s×s 格子的訊雜比（每像素比值 × s）：

```
g_r = σ(a·log(CNR_r + ε) + c·log(1 − sat + ε) + 2·log s + d_r [+ δ_r])
g_e = σ(b·log(SNR_e + ε) + 2·log s + d_e [+ δ_e])
SNR_e = relu(n − n_floor) / sqrt(n + 0.01)     n_floor = 16×16 格子平均事件數的第 10 百分位
neck = g_r·f_r + g_e·P(f_e)                     g_r = g_e = 1 時就是 add
```

純量學習率 ×30。結果：只用物理先驗 `relp2_add` 驗證集 **43.1**（比 add +0.4，最後一個 epoch +0.8），
加學習修正 δ 的 `rel2_add` 42.2。δ 在 P3 把 event 增益壓到 0.15–0.25；只用先驗時 P3 的 b 從 2.0 降到 1.63、
d_e 降到 −0.46，P4、P5 的增益都接近 1。兩者方向一致：最細的一層 event 特徵雜訊大，網路想減弱它。

### 第 3 輪：分支輔助 loss（`relp2_add --aux 0.5`）

照第 4 節加 L = L_fuse + λ·(L_r + L_e)，λ 從 0.5 線性降到 0，共用的 neck 和偵測頭各跑一次只有 g_r·f_r、
只有 g_e·P(f_e) 的輸入。驗證集 38.6（兩條分支）／ 39.6（只有 event），第 1 個 epoch 就掉約 4.5 分。
event 增益確實被拉高（P3 0.80 → 0.95），但整體變差。

**檢討**：輔助 loss 要求同一個偵測頭也能單獨從 event 特徵偵測（event 單流驗證集只有 21.2），把共用頭往 event 單流的
方向拉；第 4 節的推導沒有考慮偵測頭是共用的。要再試應改用每條分支各自的輕量偵測頭（訓練完丟掉），或 λ ≤ 0.1。

### 目前結論與下一步

1. 最好的是 v2 只用物理先驗（`relp2_add`），但只有單一 seed、只多 0.4，還要多 seed 確認。
2. 學到的參數一致指向「減弱 P3 的 event」，可以把這個當先驗：例如 P3 的 d_e 初值設為負值，或 P3 不融合 event。
3. 輔助 loss 改成獨立偵測頭再試。

## 11. Softmax 模態權重（2026-11-14，分支 `softmax-fusion`）

使用者提議：依場景品質動態決定兩個模態的權重，F_fused = w_R(X)·F_RGB + w_E(X)·F_Event，
[w_R, w_E] = Softmax(MLP([F_RGB, F_Event]))。概念上白天 0.8 ／ 0.2、夜間 0.3 ／ 0.7、過曝 0.2 ／ 0.8、靜態場景 0.8 ／ 0.2；
並提醒「event 活動量高」不等於「event 品質好」（相機運動、背景變化也會產生大量事件）。

**實作**（`SoftmaxModalityGate`）：每張圖、每個尺度（P3–P5）取兩條分支特徵的 GAP 與 GMP（4C 維），
經 MLP（4C → max(C/4, 32) → 2）與 Softmax 得到 [w_R, w_E]，neck = w_R·F_rgb + w_E·P(F_evt)。MLP 讀的是 backbone 特徵
而不是原始事件數，所以有機會學到「事件多但不可靠」。MLP 最後一層零初始化（兩模態等權），P 為恆等初始化的 1×1 conv。
`sw_` 權重和為 1，初始 0.5 ／ 0.5（neck 尺度只有 add 的一半）；`sw2_` 權重和為 2，初始 (1, 1) 即 add。

**結果**（短排程 5 epoch、lr 1e-3、seed 0；mAP50-95）：

| 模型 | 驗證集 | test | 白天 | 偏暗 | 夜間 | w_E（白天／偏暗／夜間） |
|---|---|---|---|---|---|---|
| add | **42.7** | 51.1 | 51.6 | 59.3 | 38.1 | — |
| `sw_add` | 42.2 | 51.9 | 52.0 | 60.4 | 38.9 | 0.198 ／ 0.198 ／ 0.198 |
| `sw2_add` | 42.6 | 51.7 | 51.9 | 60.2 | 39.1 | 0.198 ／ 0.198 ／ 0.197 |

兩者驗證集都在第 1 個 epoch 最高（42.2 ／ 42.6），之後降到 40.5 左右，第 5 個 epoch 回到 41.9 ／ 42.0。

**檢討**：

1. 依驗證集沒有進步；test 高 0.6–0.8 不能拿來做決定。
2. 權重沒有隨場景改變：w_E 在所有光線下都約 0.20，等於學到一組固定比例。RGB 破壞評估（step 12A）中，
   破壞從強度 1 加到 5，w_E 也只在 0.195–0.201 之間，概念表的假設沒有成立。
3. 推測原因：DSEC 訓練資料的 RGB 幾乎都可用（夜間 RGB 對比雜訊比沒有下降，第 2 節），讓 RGB 權重高永遠是對的，
   MLP 沒有訓練訊號學會在 RGB 變差時轉向 event。要讓權重真的依場景改變，訓練時需要 RGB 品質變差的樣本，
   例如 RGB 破壞增強，或 FRN（Cao et al., ECCV 2024）訓練時以 15% 機率把 RGB 輸入歸零的做法。
